# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A single playable Super Mario World level in the browser, built on **Phaser 4.2.1** with **no build step**. The engine is vendored, the source is plain ES modules, and deploying is copying the folder onto a static host.

```
index.html            <script type="module" src="src/main.js">
lib/                  phaser.esm.min.js, vendored (1.3 MB, ~345 KB gzipped)
docs/skills/          Phaser 4.2.1's own SKILL.md docs, pinned to the vendored build
tools/build_assets.py the asset pipeline
assets/src/           raw sprite rips -- inputs only, never loaded by the game
assets/gen/           GENERATED by the pipeline; never hand-edit
assets/audio/         SFX and music
src/                  game code
legacy/               the 2015 Phaser 2 version, kept for reference only
```

## Running it

```bash
python3 -m http.server 8000     # then http://localhost:8000/
```

**It must be served over HTTP.** `file://` fails harder than it did under Phaser 2 — ES modules are blocked by CORS, not just XHR. (Any real host is fine; this only affects double-clicking `index.html` locally.)

While iterating, serve with caching disabled. Chrome caches ES modules aggressively and will happily keep running a stale `src/*.js` through repeated reloads, which produces genuinely baffling debugging sessions:

```python
class H(http.server.SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header('Cache-Control', 'no-store')
        super().end_headers()
```

## Deploying

This lives inside the Jekyll site repo (`travispwingo.github.io`) as the `mario/`
directory and is published at **traviswingo.com/mario/**. It is all static files,
so there is nothing to build and no server logic — commit and push, and GitHub
Pages serves it.

Two things about that host worth knowing before moving anything:

- **The site's root `.gitignore` has a bare `vendor` entry**, which git matches at
  any depth. The engine lives in `lib/`, not `vendor/`, specifically so it does
  not get silently dropped from the commit — renaming it back would 404 the game
  in a way that looks fine locally.
- **Jekyll passes this through untouched.** Files without YAML front matter are
  static files and are copied verbatim, `index.html` included. Do not add a
  root `.nojekyll` to "fix" anything — that would disable Jekyll for the whole
  blog.

`assets/src/`, `docs/` and `legacy/` are ~3 MB of dev-only material that no
visitor ever fetches. They are kept so the pipeline can be re-run from source;
delete them if the repo size ever matters.

## The asset pipeline

`python3 tools/build_assets.py` regenerates everything in `assets/gen/`. Run it after touching anything in `assets/src/`. It is deterministic — same inputs produce byte-identical output.

It exists because the raw rips cannot be used directly:

- **Two sheets are colour-keyed, not alpha.** `mario-objects.png` carries `tRNS` magenta `(255,174,201)`, `mario-enemies.png` blue `(112,146,190)`. Loaded as-is they render with coloured rectangles around every sprite.
- **Transparent pixels carry leftover background colour**, so filtered sampling haloes the sprite edges. The pipeline overwrites the RGB of transparent pixels with their nearest opaque neighbour.
- **Scales differ.** The SMW object and enemy rips are 2x nearest-neighbour upscales of the 16x16 originals; `smw-mario.png` and the SMB1 sheets are 1x. Everything is normalised to **2x**, so the game has one world scale and `TILE = 32`.
- **Nothing is on a uniform grid**, so a tileset for `TilemapLayer` has to be cropped and repacked, with 1px edge extrusion to stop seams at fractional zoom.

Frames are named positionally (`mario_r4_c8` = row band 4, sprite 8) so the pipeline stays mechanical. The mapping from positions to poses lives in `src/frames.js` — that is the file to edit when a pose looks wrong, not the pipeline.

A useful property of these sheets: **every row is mirror-symmetric**, so only right-facing frames are listed and `setFlipX` handles the rest.

## Architecture

`main.js` builds the game and registers four scenes: `Boot` (load) → `Title` → `Level` + `Hud`. Tunables live in `config.js`; the level is a hand-authored ASCII map in `level1.js`.

- **Terrain** is a 2D array of tile indexes fed to `make.tilemap({ data })` — no Tiled. `addTilesetImage(..., margin=1, spacing=2, firstgid=1)`; the margin/spacing match the pipeline's extrusion, and `firstgid=1` matters because `level1.js` numbers tiles from 1 so 0 and -1 can both mean empty.
- **Pipes, ? blocks, coins, the flagpole and the castle** are atlas sprites with their own bodies, not tiles. They are not on the 32px lattice and the ones that animate could not be tiles anyway.

## Things that will bite you

These are all bugs that were hit and fixed here; the fixes are load-bearing.

1. **Never tween the position of a dynamic Arcade body.** The body writes the transform back every step, so the tween silently does nothing. Move it with velocity, or disable the body (`body.enable = false`) and let the tween own the transform — which is what the flagpole cutscene does.

2. **`blocked.down` flickers false for single frames** while running over flat ground. Testing `JustDown(jump) && onGround` therefore throws away real jump presses. Read `JustDown` unconditionally into a buffer and pair it with a coyote-time window (see `Player.update`).

3. **An Arcade body does not follow a frame size change.** Frames here are tight-cropped and differ in height (big Mario's jump is 62px against 56 idle), so the body offset is recomputed every tick in `Player.syncBody()`. Without it Mario hovers on some frames and sinks into the floor on others.

4. **`game.sound.mute` does not read back synchronously.** Phaser 4 backs it with a Web Audio gain node — the getter is `masterMuteNode.gain.value === 0` and the setter schedules the change. `!game.sound.mute` reads a stale value, so `audio.js` keeps the authoritative flag and treats Phaser and localStorage as followers.

5. **Scene-scoped key handlers are re-registered on every `scene.restart()`**, and the level restarts on every death. Two handlers means a toggle cancels itself out. Page-level bindings (mute, in `main.js`) do not drift.

6. **`scene.restart()` re-runs `create()`**, so anything that must survive a death goes through `init(data)`. Otherwise lives reset and the game can never end.

7. **A static body sizes itself from its game object.** `setSize()` followed by `updateFromGameObject()` is overwritten. Use a Zone, which carries real dimensions — see `makePipe`.

## Testing in a hidden tab

Browser automation leaves the tab hidden, which pauses `requestAnimationFrame` entirely. To drive the game by hand you must advance **both** clocks Phaser reads — `performance.now()` for `TimeStep`, `Date.now()` for the `TweenManager` — and pass the timestamp to `loop.step()`:

```js
const pn0 = performance.now(), dn0 = Date.now();
window.__vt = pn0;
performance.now = () => window.__vt;
Date.now = () => dn0 + (window.__vt - pn0);
const drive = (n = 60, dt = 1000 / 60) => {
    for (let i = 0; i < n; i++) { window.__vt += dt; game.loop.step(window.__vt); }
};
```

Patch only one of the two and physics will advance while tweens and timers appear frozen — which reads exactly like a game bug and is not one.

## Level design constraints

Measured from the current tuning in `config.js`; recheck if you change the jump.

- Max jump: **3.6 tiles up**, **3.8 tiles across walking**, **6.8 running**.
- So a platform more than 3 tiles above its approach is unreachable, and a gap wider than 3 tiles needs the run button.
- Enemies do **not** stop at ledges by default. An enemy that refuses to walk off a pit parks on the rim, exactly where the player lands after jumping it. Only Koopas set `stopsAtLedges`.
